> 版本：v0.2 ｜ 更新：2026-11-10

## 1. 五条工作流逐个展开

### 场景 ① 审合同

**适合**：拿到一份商事合同，要快速找风险条款、知道依据、拿到修改建议。
**不适合**：复杂并购条款谈判、需要律师实质判断的部分——规则引擎只做初筛。

| 步 | 你做什么 | 系统做什么 | 功能 | 输出 |
|---|---|---|---|---|
| 1 | 粘贴合同全文或片段 | 按 14 条可解释规则匹配 | B1 | 风险条款定位、分级（高/中/低）、修改建议 |
| 2 | — | 把每条风险的依据法条送去结构化查库 | A1 A2 A3 | 六态核验结果；已废止 / 虚构条号直接拦截 |
| 3 | 看右侧核验面板 | 逐条展示状态与出处 | A2 | `demo_only`（演示）或 `verified`（权威库） |
| 4 | 逐条确认签字 + 文档整体签字 | 复核闸门校验 | A4 | 未完成则导出按钮不可用 |
| 5 | 导出 / 下载 | 生成四件套 + 留痕 | A5 A7 A8 | 风险报告 / 核验明细 / 复核记录 / AI 使用声明 |

**入口**：左侧 `审合同` → 点「开始审查」。示例文本已预填，可直接点。
**验收**：高风险条款被标红、依据法条全部出现在右侧核验面板、未签字时导出被拒。

---

### 场景 ② 问法律问题

**适合**：需要一段带出处的法律分析，且不允许模型凭记忆编法条。

| 步 | 你做什么 | 系统做什么 | 功能 |
|---|---|---|---|
| 1 | 输入问题或选快捷问题 | 先把输入与历史消息一起做数据分级 | A6 |
| 2 | — | 绝密级（A 类）直接阻断外部模型调用 | A6 |
| 3 | — | Agent 拆解 → 工具检索 → 结果校验 | C1 C2 C3 / B2 B3 B4 |
| 4 | 看流式回答 | 工具调用卡片可见，过程文本与最终回答分离 | C3 |
| 5 | — | 回答里的每条引用自动进入核验队列 | A1 A2 |
| 6 | 复核签字 | 逐条确认后可导出 | A4 / A7 |

**入口**：左侧 `问法律问题` → 选一条快捷问题（会自动演示完整链路）。
**注意**：演示页是浏览器本地模拟，不调用真实模型；真实部署接任意 OpenAI 兼容接口。

---

### 场景 ③ 核验引用

**适合**：收到 AI 生成的文书、对方材料、旧合同，想确认法条和案号是不是真的。
**这是最独立的场景**——不需要生成回答，只要体检。

| 步 | 系统做什么 | 功能 |
|---|---|---|
| 1 | 抽取《…》第 N 条、款项、案号、残缺引用 | A1（中文数字与别名归一） |
| 2 | 按「法名 + 条号」精确查库，不用语义相似 | A2 |
| 3 | 输出六态：`verified` / `repealed` / `not_in_corpus` / `demo_only` / `malformed` / `needs_human` | A2 A3 |
| 4 | 已废止（如《合同法》第 52 条）、库中不存在、格式异常一律标红并要求转人工 | A3 A4 |

**入口**：左侧 `核验引用` → 点「逐条核验」。示例文本故意混了废止法条、编造条号、演示案号和残缺引用，一次能看到四种状态。
**红线**：语义相似 ≠ 法条命中，存在性与时效绝不交给模型判断。

---

### 场景 ④ 合规交付

**适合**：要提交给客户、法院或归档，必须有签字、留痕和《AI 使用声明》。

| 步 | 做什么 | 功能 |
|---|---|---|
| 1 | 先在 ① 或 ② 生成正文 | B1 / C2 |
| 2 | 引用核验全部完成 | A1–A3 |
| 3 | 逐条签字 + 文档整体签字（缺一不可） | A4 |
| 4 | 导出四件套 | A7 A8 |
| 5 | 审计链记录 who / when / tool / citation / verification / reviewer / export | A5 |
| 6 | 下载 `.md` 归档 | F1 F3 |

**入口**：左侧 `合规交付`。页面直接显示签字进度条和待签项。
**闸门规则**：未签字 → 403；含已废止 / 库中不存在 / 格式异常引用 → 即使签完字也禁止导出。

### 场景 ⑤ 团队协作与接入

**适合**：从「一个人用」变成「一个团队用」，或要把能力接到 Claude / WorkBuddy。

| 需求 | 用哪个 | 功能 |
|---|---|---|
| 把审查经验沉淀成可复用清单 | Skill 中心（版本化、必填项校验、导入导出） | C4 |
| 归集案件事实、发现材料矛盾与缺口 | 案件事实层（每条带出处、矛盾挂起不合并） | C5 |
| 多人项目隔离 / 利益冲突 | 伦理墙（被排除项目根本不出现在列表里） | E1 |
| 权威数据源挂了怎么办 | 健康检查 + 降级；降级后核验自动转 `demo_only` | E2 |
| 想看用量 | 按会话工具调用与 token 估算（非计费口径） | E3 |
| 接进别的 Agent | MCP Server：`npm run mcp`，6 个工具，stdio JSON-RPC | D4 |

**入口**：左侧 `团队协作与接入` → 可切换用户查看伦理墙效果。

## 3. 三条通用规则（所有场景都适用）

1. **语义相似 ≠ 法条命中。** 引用的存在性、条号、时效必须结构化查库，模型只负责组织语言，不裁决「这条法条存不存在」。
2. **AI 可以提议，不能落定。** 任何对外交付物都要人工逐条签字，未签字禁止导出；责任不因使用 AI 减免。
3. **演示数据绝不伪装成权威数据。** 法条只存编号 + 效力 + 主旨摘要，案号统一 `DEMO-CASE-YYYY-NNN`，命中演示语料只返回 `demo_only`，绝不写成 `verified`。

## 4. 三步上手

1. 打开演示链接，默认就是 `使用说明`，从 5 张场景卡里选一个。
2. 按页面顶部的步骤条一步步点；每个页面都会写明「本页属于哪个需求、工作流第几步、用到哪些功能编号」。
3. 想看完整闭环，直接点 `问法律问题` 的第一条快捷问题，一次走完工具调用 → 回答 → 核验 → 签字 → 导出。

真实部署：`npm install && npm run dev`（零密钥可跑），配置 `.env` 接模型与权威数据源，详见仓库 README。

## 5. 常见问题（按需求归类）

| 现象 | 原因 | 怎么处理 |
|---|---|---|
| 引用状态都是 `demo_only` | 用的是演示语料，不是权威库 | 正常；接北大法宝 / 企查查等已授权 MCP 后才会出现 `verified` |
| 导出按钮是灰的 | 未完成逐条签字，或存在阻断引用 | 按右侧面板逐条签字；若有红色状态，先修正正文重新生成 |
| 合同审查一条都没命中 | 演示规则库只有 14 条模式 | 不代表合同无风险，关键条款仍须人工复核 |
| 输入里带身份证号被拦 | A 类绝密数据触发数据分级路由 | 符合设计：敏感数据不出域，请脱敏或改用内网自建模型 |
| 想要「零幻觉」承诺 | 不提供 | 法律专用 RAG 实测仍有 17%–34% 幻觉率，本项目用三道防线 + 人工终审，不宣称零幻觉 |

## 6. 演示页 vs 真实部署

| | 在线演示页 | 仓库真实部署 |
|---|---|---|
| 模型 | 浏览器本地模拟（4 套预设回答） | OpenAI 兼容流式接口 / Mock LLM |
| 数据源 | 内置 DEMO 语料（浏览器内） | 本地 DEMO / HTTP / MCP 权威源，支持降级 |
| 持久化 | 刷新即重置 | 四张 append-only JSONL，重启回放 |
| MCP | 仅展示工具清单 | `npm run mcp` 真实 stdio 服务 |
| 用途 | 快速体验交互与工作流 | 实际工程使用与二次开发 |
